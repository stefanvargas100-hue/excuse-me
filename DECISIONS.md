# Decisions

- Keep the web codebase and wrap it later (Capacitor) instead of rewriting; see ROADMAP.md.
- GitHub repo will be private at first; can go public when hosting on GitHub Pages.
- Solo project: work on main, push directly.
- Phase 1: split the single file into index.html, style.css, game.js with no code changes (low risk); original kept in git history.
- Service worker is cache-first; bump CACHE in sw.js whenever game files change, or players keep the old version.
- Icons are generated by icons/make-icons.js (no dependencies); placeholder art, replace in Phase 5.
- Fonts still load from Google Fonts (cached after first visit); bundle locally later if offline-first-run matters.
- Radar: circular, bottom right, 7 m range, forward is up; replaces the "behind you" strip.
- Limb glitch fix: arms/legs now sort by shoulder/hip depth (not the swinging hand/foot) and walk amount eases in/out instead of snapping.
- Spawning: nothing is drawn past 62 m and every spawn lands beyond 66 m, so people always walk in. Rivals spawn behind or far ahead. Tutorial-end crowd fades in.
- Removed the on-screen control tips (hint box and HOLD/DASH labels); the tutorial and the start-screen How to play now teach controls. Radar moved to the bottom corner.
- Online plan: shared-crowd races first, front-runner-wins cut-offs as a later step; own anonymous accounts and generated names before any Game Center sign-in.
- Phase 2 work lives on branch phase-2 so the live game (served from main) stays stable for playtesters. Tests run headless in Node with a stub DOM (test/harness.js); CI runs npm test on every push.
- Steering smoothness: camera follow is frame-rate independent, frame times are averaged over 4 frames, and the drawn character uses the final position of each step.
- Phase 2 split: game.js became ES modules in src/ (config, input, sim, render, audio, save, ui), generated by script from scope analysis, not hand-moved. Checked: same daily seed + same scripted inputs give identical state to the old single file on all three levels.
- Listener wiring runs from main.js (init functions) so module load order cannot matter; a load-order bug showed up in the production build and was fixed this way.
- Build: Vite. The build writes the service worker's file list and a content-based cache version, so no manual cache bumping any more.
- Deploy: Pages must be switched to "GitHub Actions" BEFORE merging phase-2 into main, or the live link breaks (main would serve unbuilt source).
- Goal changed (Nov 2026): launch with a fuller game (race mode, online, more stages) instead of shipping minimal and adding after. Downloadable/installable goal is done.
- Race mode (first version): A to B on any stage, 3 bots, 3-2-1-GO start. A bump = 30% speed for 1.3 s, then 1.6 s of passing through people (blinking) so one bump costs one penalty; it also breaks your chain. No time limit, no game over; the race ends when you cross the line. Bots steer with their own lane-finding, burst now and then, and miss people sometimes (Easy/Medium/Hard = pace and miss rate). Bots do not collide with you. Place and best win time are saved per stage.
- Bots use their own random numbers so the crowd stays identical regardless of bots (needed later for fair online races).
- Race update: people are solid (no pass-through): a bump stops you, slows you to 30% for 1.3 s, and stumbles the person aside; staying in contact counts as one bump. Safety net: pinned for 1.8 s means a brief slip-through, so nobody can stay stuck.
- Stuck-on-wall fix: a missed key release or touch end could leave a phantom direction that cancelled your real input (left + right = nothing) and pinned you to a wall. Newest key now wins, and focus loss or any touch end releases everything. Reproduced in a test first.
- Race pace: combos add speed (+2.5% per level, up to +17.5% at x8); low stamina slows walking (up to -20% at zero). Same rules for bots. The race HUD shows PACE % instead of score.
- Bots: look further ahead, plan overtakes early, drift side to side on clear road, dash around trouble and burst on clear road. Hard: faster, almost never miss people, dash readily.
- UI restyled as hand-drawn: cream paper with notebook lines, thick ink outlines, wobbly corners, hard offset shadows, highlighter yellow. Fonts: Permanent Marker (headings) and Patrick Hand (text). The 3D scene itself is unchanged.
- Colour scheme: Candy pop (deep purple ink, warm cream paper, hot and soft pink, teal, yellow, violet). Stamina bar shifts green, yellow, orange, red as it drops, and in a race a red tag shows the speed it is costing you. Bots get random names from a list of 100 (src/config/names.js).
- Removed the notebook-line background from cards (plain cream paper).
- Updates: when the installed app finds a newer version it switches to it automatically if you are on the menu screen (never mid-run); otherwise it applies on the next launch.
- Modes (Nov 2026): Classic, Daily and Weekly are endless (no finish line, no clock, run until you bump); only Race has a goal. Classic: any of the 3 stages, best score per stage. Daily and Weekly: one try per day/week (remembered on the device; quitting mid-run still uses the try), the stage and crowd come from the date/ISO week. The crowd is built in seeded pieces (per 4 m chunk, per crosswalk), so everyone meets the same people in the same places whatever pace they take; timed surprises (rivals, speedsters, rush hour) follow the same script order but their spots depend on your pace.
- Stage stars still work: reach the old goal distance, hit the score target, chain of 15.
- Leaderboards need a server and are NOT built yet. Only your own best (per stage; today's and this week's score) is saved on the device. The one-try rule is also only enforced on the device until there is a server.
- Balance after Hard-in-NYC playtest: "Excuse me" now moves up to 4 people (was 2), out to 7.5 m (was 6) and 2 m wide (was 1.6), they stay aside 1.3 s (was 1.0), recharge 5.5 s (was 6). Stamina slowdown only starts below 40 (8% by 10, up to 35% when completely out). Bot pace trimmed about 3% so the lighter stamina penalty does not make bots faster than you playtested (Hard NYC still about 156 s).
- Race stats: top speed, acceleration, recovery, race mode only; classic, daily and weekly ignore them. Build sets the base (small: accel up, speed down; medium: balanced; large: speed and a little recovery up, accel down). Gear types add trade-offs that sum to zero; colours never count. Male/female is looks only, and the hitbox is the same for every build. Capped at 10 points per stat (about +/-6% speed, +/-50% accel, +/-40% stamina refill).
- Every gear slot must be filled. Only the headpiece can be hidden, and it keeps its stats when hidden. Shades moved into the headpiece slot; a sling bag replaces "no backpack". Bots get random builds and gear under the same rules.
- Races start from a standstill so acceleration counts.
- Slipstream (race only): 1.2 s within 4 m behind someone walking your way, within 0.6 m sideways, earns +18% speed for 2.5 s. Works behind crowd walkers and racers, bots use it too, and a bump cancels it.
- Endless difficulty: ramps to its hardest by the old goal distance and stays there. More random crowd events later is an open idea, not built.
